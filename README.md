# HuEVOCINO 🎰

Казино-портал: crash-игра «Взлёт», 13 слотов, блэкджек, покер, крэш-раунды и **15 аркад**. Монеты — внутриигровая валюта (реальных денег нет). Бренд и дизайн — красная тема HuEVOCINO.

Жанровая механика, собственный код, дизайн и название — копирование чужих ассетов не используется.

## Стек

- `backend/` — Node.js + Express + TypeScript, JSON-файловое хранилище (`data.json`), SSE-стрим краша. Порт **4200**.
- `frontend/` — React + Vite + TypeScript + zustand. Dev-порт **5176** (прокси `/api` → 4200).

## Запуск

```bash
# бэкенд
cd backend
npm install
npm run dev          # http://localhost:4200

# фронтенд (второй терминал)
cd frontend
npm install
npm run dev          # http://localhost:5176
```

Тесты: `cd backend && npx vitest run` (68 тестов).

## Как играется

1. Выбираешь ставку (10–100 000) → **«В ВОЗДУХ»**.
2. Множитель растёт: `m(t) = e^(t/2800мс)` (2× примерно за 1.9 сек).
3. **«ЗАБРАТЬ»** — фиксируешь `floor(ставка × множитель)`.
4. Упал раньше — ставка сгорает. Раунд в гонке не начать.

Краш считает сервер (`rollCrash`): `max(1, floor(0.97/(1−r)·100)/100)`, r — равномерный из `crypto.randomBytes` → ~50% раундов ниже 2×, ~1% выше 100×, матожидание стратегии «вывести на пороге» = 0.97 ставки (house edge 3%). Клиент момент падения не знает заранее — сервер присылает событие `crash` по SSE; кэшаут сервер проверяет по своим часам.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/state` | баланс, история, статистика, активный раунд |
| POST | `/api/round/start` | `{bet}` → начало раунда |
| GET | `/api/round/:id/stream` | SSE: событие `{event:"crash", crashAt}` |
| POST | `/api/round/cashout` | `{id}` → `{multiplier, payout, balance}` |
| POST | `/api/faucet` | +1000 демо-монет |
| POST | `/api/topup` | демо-пополнение с комиссией (заголовок `Idempotency-Key`) |
| POST | `/api/login` | вход huEVO (проверка подписи `hu_*`) |
| POST | `/api/topup/huevo` | создание платежа через huEVO API |
| POST | `/api/topup/huevo/check` | подтверждение и зачисление |
| POST | `/api/huevo/callback` | вебхук huEVO (проверка `X-Huevo-Signature`) |
| GET/POST | `/api/admin/commission` | комиссия (заголовок `x-admin-key`) |
| GET | `/api/arcade` | список 15 аркад-игр |
| GET | `/api/arcade/:id/state` | текущее состояние игры |
| POST | `/api/arcade/:id` | действие `{action, ...}` → `{view, balance}` |
| POST | `/api/slots/:id/spin` | спин слота (форс-выигрыш каждую 10-ю) |

Идентичность: заголовок `x-session` (вход huEVO) или `x-device-id` (UUID); `DEV_AUTH=true` — фолбэк без заголовка.

## Комиссия

При пополнении удерживается комиссия (по умолчанию **5%**) и копится в казне платформы (`treasury`): `net = amount − floor(amount×percent/100)`. Настройка: `POST /api/admin/commission {percent, enabled}` с `x-admin-key`.

## Интеграция huEVO

Полностью повторена схема из основного проекта:

- SDK: `<script src="https://huevo.su/static/js/huevo-apps-v1.js">`, `confirmPayment(intent_id)`.
- Вход: `POST /api/login` с `location.search` → HMAC-SHA256-проверка `hu_*`-параметров → токен (`x-session`).
- Платежи: `POST /api/topup/huevo` → huEVO `/payments` (Basic auth) → `confirmPayment` → `POST /api/topup/huevo/check` (или вебхук) → зачисление один раз по `intent_id`.
- Тестовый режим huEVO: `test: true`, в истории помечается.
- Ключи в `backend/.env`: `HUEVO_CLIENT_ID`, `HUEVO_CLIENT_SECRET`, опц. `SESSION_SECRET`.
- Коллбек в настройках приложения: `https://<домен>/api/huevo/callback`.

## Статус

Работает локально: device-режим, раунды, кэшаут, комиссия, демо-пополнение. Для реальных оплат нужны ключи huEVO.
